# 无人值守问诊处理单（C2）

> 用途：这份处理单定义"**没人回答问题**时怎么办"。体检解读是长流程、用户常常
> 零介入 —— 设计假设不是"关键点有人确认"，而是"**任何步骤都不阻塞等人**"。
> 问诊因此是**可选增强**：有回答就用，没回答就按本单的默认代入继续，
> 并把不确定性以"敏感性区间"的形式写进报告。

## 一、三个来源，一个口径

问诊项的来源（`scripts/ask_queue.py` 自动推断，≤5 问）：

| 来源 | 是什么 | 例子 |
|---|---|---|
| A | 规则 `input_fields` 里"没有数据"的标准项 | 吸烟/家族史/饮酒 |
| B① | 机构建议过、但数据里未见执行的检查 | 「建议增强检查」后来做了吗 |
| B② | 能解除/降级现有黄红级的测量 | 家庭血压 7 天平均 |
| B③ | 数据质量疑点的确认项 | 是否换过检测方法 / 是否重测 |

**统一口径（本案例实际执行的做法，现已固化）**：

1. **能代的先代**：报告内页字段优先代入 —— 家族史如果报告里写了就按报告写；
   单位/字段名/日期一律取自内页，不问。
2. **代不了就给默认 + 敏感性**：每个问诊项都带一条"无人应答时的默认代入"
   （见 `ask_queue.py` 生成的最后一列），默认取**保守侧**（就高不就低）：
   * 吸烟 → 按「不吸烟」代入（不给筛查资格）；若 ≥30 包年 → 补"资格成立"的上界句；
   * 家族史 → 按「无」代入；若阳性 → 风险上浮一档，报告给"若阳性会怎样"；
   * 饮酒 → 按「少量/不饮」代入（不给解释项）；
   * 家庭血压 → 按**诊室单次读数**谨慎处理（不解除）；若 <130/80 → 降一级；
   * 随访是否执行 → 按「未见执行」代入（卡片继续挂着）；若已做过且正常 → 降级；
   * 检测方法是否变更 → 按「无法核实」代入（措辞锁「无法核实」，不写"正常/已排除"）。
3. **不阻塞**：`ask_queue.py --check` 只断言"必问项在队列里"，**不要求回答**。
   报告照常产出；问诊答案到达后**增量修订**（改的是解释与级别，不动已核对的数值）。

## 二、处理单（可复制）

```
【无人值守问诊处理单】
受检者：<姓名>   数据源：<产物目录>   生成：ask_queue.py --engine-out <out>

1) 问诊是可选的吗？           → 是。无回答 = 按"默认代入"继续，不阻塞。
2) 默认代入从哪来？           → ask_queue.py 输出的最后一列（每条自带）。
3) 敏感性写在哪？             → 报告"需要确认"处写"若阳性/若做过会怎样"的上下界。
4) 数值会不会因默认代入变？    → 不会。数值一律来自报告原文（可回查页码）。
5) 谁对"默认代入"负责？        → 机器决定清单（C1）：决定 + 依据 + 不确定标记。
6) 人还能做什么？             → 事后抽检（C3 抽检单，≤5 条）；不影响正确性。
7) 回答晚到了怎么办？          → 增量修订：只改解释/级别，重跑对账即可。
```

## 三、不合格用法（会被验收链拦下）

* 把默认代入**当成事实**写（"不吸烟"写成"确认不吸烟"）→ 对账措辞检查会报；
* 用默认代入**改数值**（数值只能来自报告原文与引擎产物）；
* 因为有问诊项没回答就**停住不产出报告**（无人值守下这是错的）。
