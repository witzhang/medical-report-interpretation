# 数据契约

给**下游 agent** 的字段级说明。所有枚举值都取自真实产物，不是手写。

---

## 一、两条轴（**最重要的一条设计**）

引擎**从不**把"这项正常吗"压成一个布尔。它分两条轴，各自独立：

### 位置轴 `Finding` —— 这一次的测量值相对参考区间

| 值 | 含义 | 什么时候是它 |
|---|---|---|
| `normal` | 在区间内 | |
| `abnormal` | 在区间外 | |
| `undetermined` | **本该能判，但数值解析不出来** | 数值项读成空、单位判不了 |
| `not_assessable` | **缺输入**（没有参考区间，或该年没测） | 报告没给区间 |
| `not_applicable` | **人群不适用** | 男性项目用在女性身上 |

> **`not_applicable` 优先于 `not_assessable`。** 一个人群不适用的项目，
> 就算数据齐全也不该判 —— 先问"适不适用"，再问"有没有数据"。

### 变化轴 `Change` —— 跨年变化是否超过 RCV

| 值 | 含义 |
|---|---|
| `beyond_noise` | 变化超过 RCV 阈值（`√2·1.96·√(CVi²+CVa²)`）|
| `within_noise` | 在噪声内，**不能说它变了** |
| `insufficient_points` | 可比年数不足，或单位不可比 —— **拒绝出趋势** |

引擎对每个指标做**三次两两比较**：24→25、25→26、**24→26**。
只做相邻比较会漏掉跨度最大的那一对（本案例里肌酸激酶的 +58.5% 就在 24→26 上）。

**位置正常 ≠ 没变化。** 两条轴要一起看：一个项目可以三年都在区间内，
但 24→26 的变化远超噪声 —— 那才是有信息量的。

## 二、结论对象 `Conclusion`

`conclusions.csv` 的列：

| 列 | 类型 | 含义 |
|---|---|---|
| `id` | str | 稳定 id，形如 `C01`（`C` + 两位序号）|
| `分类` | enum | `confirmed` / `to_verify` / `to_followup` / `data_quality` |
| `共同上游` | str | 这条结论由哪一组指标共同支撑（用于归并）|
| `结论` | str | 正文（**不含诊断**）|
| `不确定性` | enum | `low` / `medium` / `high` |
| `断言类型` | enum | `informational` / `advisory` / `red_flag` |
| `建议动作` | str | 可执行的动作提示 |
| `规则` | str | 引用到的规则 id，**可为空**（如纯数据质量提示）；非空时可追到 `checkup/rules.py` 的 `Provenance` |
| `证据` | str | **指回报告页与原文** |

### `分类` 的含义

| 值 | 意思是 |
|---|---|
| `confirmed` | 有依据、可下结论 |
| `to_verify` | 需要复核（如变化超噪声但只测过一次）|
| `to_followup` | 需要随访 |
| `data_quality` | **这条是说数据本身有问题**，不是医学结论 |

### `断言类型` 的边界

| 值 | 允许说什么 | 依据 |
|---|---|---|
| `informational` | 陈述事实与数值 | —— |
| `advisory` | 建议复查/就诊 | —— |
| `red_flag` | 危急值，必须立即就医 | 《健康体检重要异常结果管理专家共识》A 类 |
| ~~诊断~~ | **禁止** | FDA CDS 指南；《互联网诊疗管理办法》第十六条 |

措辞分层由 `render.classify_wording()` 强制，`render.lint()` 会拦下越界措辞。

## 三、观测对象

### `report_<年>.json`

```jsonc
{
  "document": {                    // 这一份报告的元信息
    "doc_id": "...",
    "org_id": "NX-001",            // 机构 id，对应 catalog/templates/<id>.json
    "exam_date": "2026-08-20",     // **从内页读**，不用文件名
    "page_count": 11,
    "carrier": "text",             // text | image —— v1 只支持 text
    "template_version": "v1",
    "age": 35,
    "sex": "男",
    "notes": []
  },
  "observations": [ /* 见下 */ ],
  "narratives": [ /* 彩超/CT/心电图/骨密度的叙述条目 */ ],
  "institution_findings": [ /* 机构主检报告自报的异常项 */ ]
}
```

### `observations[]`（原始层，`value_text` 保真）

| 字段 | 含义 |
|---|---|
| `year` / `page_no` / `section` | 年份、页码、段落名 |
| `item_raw` | **报告上的原始项目名**，未改写 |
| `value_text` | **报告上的原始数值串**，未改写 |
| `value` | 解析后的数值（`null` 表示解析不出）|
| `unit` | 报告上的单位 |
| `qualifier` | 定性描述（如「阴性」）|

### `normalized_observations.csv`（归一后）

在原始字段之外增加：

| 字段 | 含义 |
|---|---|
| `analyte_id` | 归一后的稳定 id（如 `CHEM.甘油三酯`）|
| `matched_by` | 靠什么匹配上的（项目名/单位/机构规则）|
| `unit_status` | 单位是否等价、是否冲突 |
| `repaired_by` | 用了哪条修复规则（如 `NX-001.RDW.SWAP`）|
| `ref_low` `ref_high` `ref_op` `ref_raw` | 参考区间 |
| `flag` | 引擎算出的越线标记 |
| `pdf_flag` | **报告自己印的箭头**（两者应一致，不一致会进 L3 校验）|
| `evidence` | 出处指针 |

> **原始值永不改写。** `item_raw` / `value_text` 保留报告原样，
> 归一结果写在新字段里。任何"修复"都必须在 `repaired_by` 留名。

## 四、判定对象 `judgements.csv`

一行 = 一个指标。

| 列 | 含义 |
|---|---|
| `analyte_id` `项目` `段落` `单位` | 身份 |
| `CVi%` `RCV阈值%` `研究数` | 个体内变异与其来源；**没有 CVi 就留空，不编造** |
| `稳健性` | `稳健超出` / `稳健在内` / `取决于CVi取值` |
| `2024` `2025` `2026` | 逐年值 |
| `位置2024...` | 位置轴（见上）|
| `区间2024...` | 参考区间（字符串形式，如 `0-1.7mmol/L`）|
| `24→25%` `25→26%` `24→26%` | 变化百分比 |
| `判24→25` `判25→26` `判24→26` | 变化轴（见上）|
| `备注` | 人类可读的补充 |

### `稳健性` 怎么读

- `稳健超出` —— 无论 CVi 取区间内哪个值，都判超出
- `稳健在内` —— 无论怎么取都判在内
- **`取决于CVi取值`** —— CVi 本身有不确定范围（不同文献值不同），
  结论会随之改变。**这种项目不能当确定结论用。**

## 五、派生对象 `derived.csv`

一行 = 一条规则 × 一个年份。

| 列 | 含义 |
|---|---|
| `rule_id` | 规则 id（如 `RENAL.EGFR_CKDEPI2021`）|
| `规则` | 人类可读名 |
| `年份` | |
| `值` `单位` `分层` | 结果 |
| `状态` | `ok` / `not_assessable` / `not_applicable` |
| `缺失输入` | **`not_assessable` 时必须说清缺什么** —— 有不变式「不可评估说明理由」强制，违反会让 `tools/health.py` 的测试失败 |
| `输入` | **JSON 串** —— 这条结果用到的全部原始值。**复核就从这里下手** |
| `说明` `备注` | |

> `输入` 那一列是**可验证性的关键**：任何一条派生结论都能原地复算。

已实现的规则见 `AGENTS.md` 的 L5 一行。

## 六、校验对象 `validation.json`

```jsonc
{
  "level": "warn",             // pass | warn | fatal
  "checks": [
    { "name": "内部恒等式", "level": "pass", "detail": "...", "items": [] }
  ]
}
```

本机三份报告跑出来是 **12 项检查**：

```
level = warn
内部恒等式:pass · 覆盖率:pass · 单位一致性:pass · Delta Check:warn
生理合理性:warn · 常数序列:warn · 重复观测:pass · 归一覆盖率:pass
化验页抽取审计:pass · 版式漂移:pass · 采样间隔:warn · 载体判定（G0）:pass
```

**`level` 取所有检查里最严重的那个**，`fatal` 优先。

| 检查 | 什么时候 fatal |
|---|---|
| 抽取审计 | 判为化验页却一项都没抽到 |
| 单位一致性 | 跨年单位不可比 |
| 生理合理性 | 身高跨年差 > 2cm（成年人不可能）|
| 载体判定 G0 | 有图无文字层 = 扫描页（**内容未被分析**）|
| 未映射率 | 超过 20% 的项目名没映射上 |

⚠ **`level != "pass"` 时，下游应当先看 `checks` 再采信结论。**

---

## 七、给下游 agent 的三条建议

1. **先看 `validation.json` 的 `level`。** 有 `fatal` 就别往下走。
2. **别把 `not_assessable` 当阴性。** 某年没做这项检查，就是没做 ——
   引擎对这种情况会明确写出「未做」，而不是「正常」。
3. **要引用结论，就连 `证据` 与 `规则` 一起引。** 单独一句正文丢掉了
   它是怎么来的，也就丢掉了可复核性。
