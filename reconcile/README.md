# reconcile —— 报告里的事实性判断，全部由脚本产出并可对账

> **位置**：skill 的 `reconcile/`（收编自工作区 `报告核对/`）。
> **数据边界（§5.6）**：本目录只放**代码与数据定义**；产物（四张底稿、对账记录、
> 复核表）一律写**用户工作目录**（`CHECKUP_OUT`，缺省 `<数据根>/体检解读_out`），
> ⛔ 不写 skill 目录（脚本对"写到 skill 里"直接报错）。

> 这是"数据准确性"这一轮的机制层。**报告形态（v6.3）不变**，变的是：
> 报告里每一处数字、每一处"缺/有"判断、每一处状态分类、每一条机构建议摘录，
> 都不再由 agent 看着 CSV 手工数出来，而是由本目录的脚本产出、并被对账器逐条核对。

## 一、命令（跑一遍就知道报告对不对）

**A. 新案例链（P0-8，换机构/换人走这条）**

```bash
# ① 引擎三件套 → 同一个产物目录（⛔ 不写 skill 目录）
cd <skill>/engine
python3 run_narrative.py --src <报告目录> --out $CHECKUP_OUT   # 抽取层
python3 run_normalize.py --src <报告目录> --out $CHECKUP_OUT   # 归一
python3 run_pipeline.py --src <报告目录> --out $CHECKUP_OUT   # 全链；版式不匹配 → 非零退出

# ② 四张底稿（吃上面那个产物目录）
cd <skill>/reconcile
python3 gen_artifacts.py --engine-out $CHECKUP_OUT --case-name <名> --out <产物>/artifacts/<名>

# ③ 对账（报告 + 两张图 spec 一起对）
python3 reconcile.py --artifacts <产物>/artifacts/<名> --engine-out $CHECKUP_OUT --case-name <名> \
  --report <报告.md> --specs <merge_spec.json> <causal_spec.json> --out <产物>/对账_<名>.md
```

**B. 回归（real / synth 两条基线，数据由 `CHECKUP_FIXTURES` 指向）**

```bash
python3 gen_artifacts.py --case real  --out /tmp/ck_real
python3 reconcile.py --artifacts /tmp/ck_real \
  --report "<报告>.md" \
  --specs "<报告>_merge_spec.json" "<报告>_causal_spec.json" \
  --out /tmp/对账_real.md

python3 gen_artifacts.py --case synth --out /tmp/ck_synth
python3 reconcile.py --case synth --artifacts /tmp/ck_synth \
  --report "$SKILL/examples/report/样例_体检报告解读_合成数据_v2.md" \
  --specs "$SKILL/examples/report/样例_merge_spec.json" "$SKILL/examples/report/样例_causal_spec.json" \
  --out /tmp/对账_synth.md
```

对账结果含逐条检查（PASS/FAIL）+"需人工确认"的数字清单。
**当前两份报告都是全 PASS（real 39/39、synth 32/32）。**未追踪数字逐条写进
「需人工确认」——数字随检查集/案例变化，以实际运行输出为准。

**C. 十五处复核（防回归）**

```bash
python3 verify_15.py --artifacts-root <两个 case 的底稿根> --out <产物>/十五处复核.md
```

## 二、四张底稿（`artifacts/<case>/`）

| 文件 | 产出什么 | 谁在用 |
|---|---|---|
| `coverage.json` | 缺口表与覆盖率：对照卫健委 2025 版基本体检项目，逐项 × 逐年判定"做过没有"，聚合出 全覆盖/部分/缺 | 附录一（整节） |
| `states.json` | 跨年状态分类：位置轴（超没超机构区间）、变化轴（是否超出它平时的正常起伏）、官方分带、**影像发现的逐年尺寸序列（带检查方式）** | 第 3/4/6/7 节的每一项表述 |
| `advice.json` | 机构建议摘录：主检条目 + **分科小结**（眼科「散瞳查眼底」这类），逐条带页码；再按主题抽"复查频率/措辞标记" | 全篇涉及机构建议的地方 |
| `facts.json` | 数值事实表：报告引用的每个数值、派生量（eGFR/China-PAR/代谢综合征/危险分层及情景）、数据质量发现、覆盖率、机构建议、影像台账 | 数字追踪与断言检查的**唯一来源** |

## 三、覆盖判定语义（**定义在此，不在 agent 脑子里**）

* **全覆盖**：该项目的全部必查子项**在每一次体检**都有记录
* **部分覆盖**：有记录但不全 —— ① 缺年份（该年套餐未含）；② 子项被拒查；
  ③ 子项门槛型项目的必查子项整块缺失
* **缺**：所有年份都没有记录
* **覆盖率** = 全覆盖项数 ÷ 应查项数（四舍五入为整数百分比）
* 「子项门槛」只对三项为真（一般检查 / 外科 / 粪便常规+隐血试验）——这三项的必查子项
  是机构报告里逐条列出的可核查清单（腰围/臀围、直肠指检…）。实验室项的子项缺失
  （如肝功能未查碱性磷酸酶）属**套餐深度差异**，记入备注、不改状态。

判定规则、适用条件（≥40 岁的肺功能/骨密度、女性专属项）与原句都写在
`guideline_2025.json`，逐条对应 `体检推荐指引文件/中国/2.基本体检项目（2025年版）.docx`。

## 四、跨年状态分类（`states.json`）

位置轴判"超没超"（用**机构当年标注的区间**），变化轴判"变没变"（用引擎的 CVi 目录与
RCV 公式：`√2·Z·√(CVi²+CVa²)`，并给出 CVi 上/下界对应的区间）。分类结果：

```
持续异常 / 新发异常 / 曾异常已回落 / 持续正常 / 临界上升 / 未评估 / 断档 / 记录类（无区间）
```

「临界上升」三级判据（**P1-A0 起来源 = 引擎 `checkup/bands.py`**，逐条标依据强度
与核实状态；对账 G15 锁"分带来源=引擎 + 逐项复算一致 + 边界值已登记"）：

1. **官方分带**（强）：血压正常高值/重点关注段、血糖与糖化前期、血脂边缘升高……
2. **eGFR 斜率**（强）：自然下降 0.4～1.0/年、KDIGO 快速进展 >5/年
3. **兜底**（弱，报告引用必须标注）：a) 方向一致且距上限 <10%；b) 距上限 <5%（贴线）

顺序有讲究：**先判噪声轴、再判余量轴** —— 否则会把"位置正常但真的在变"（肌酐那类）
误标成临界，丢掉更重要的信息。真实案例的临界项 = 总胆固醇（贴线）+ 血压（官方过渡带）。

**与引擎交叉核对**：真实案例下，本工具的位置轴/变化轴稳健性会与
`checkup-engine/out/judgements.csv` 逐项比对（对账检查 G14）——两套独立实现必须一致。

## 五、数字追踪（`reconcile.py` 第二节）

报告里每个"数值 + 单位"都要能指回某张底稿。匹配规则：**报告里的数字 = 产物值按报告
自己的显示精度四舍五入**（合成案把 mg/dL 换算后是 1.987，报告写 1.99 —— 这算一致）。

指不回的进"需人工确认"清单。人工确认后二选一：补进底稿，或登记进 `constants.json`
（指南阈值、生理常数、就医成本与时长 —— 这些不是观测数据，但也必须可指回，出处写在每一条上）。
**当前两份报告：未追踪数字逐条有交代**（尽量为 0；手算/换算类如实列出，
供人工确认——不得用跨单位巧合凑成 0）。

## 六、单位换算写在载入层（`loaders.py`）

合成案 2024/2025 用 mg/dL，报告附录二里带 `ᵐ` 的格子是换算值。**换算只发生一次**，
在 `loaders.py` 的 `CONVERSIONS`（因子 + 依据），每个换算值都带 `换算` 字段记录原值。
**参考区间与数值一起换算** —— 只换值不换区间会造出假异常（肌酐 90 μmol/L 配 0.60–1.20
mg/dL 的上限 → 判成超标 7500%），这是本工具自己踩过并写进注释的坑。

## 七、对账覆盖到什么程度（边界写清楚）

* ✅ **带单位的数字**：全量追踪（无一遗漏）
* ✅ **枚举断言**：覆盖率/缺口表、状态分类、机构建议（频率、措辞、是否标注）、
  影像台账（检查方式、逐年尺寸）、派生量（eGFR、China-PAR 含家族史敏感性、
  代谢综合征三套、危险分层与情景）、数据质量（好胆固醇同值、身高极差、采样间隔）、
  服药安全提示、优先级表述数量、"越界建议"禁则（如"吸烟者每年做 CT"）
* ⛔ **不在对账范围**：解释性与建议性文字（"为什么这件事要紧""该怎么戒"）、
  就医成本与时长（`constants.json` 人工登记）、指南阈值本身（同样登记制）

## 八、加一个新案例 / 换一家机构

1. 新案例的观测值库：真实机构 → 引擎三件套（`run_narrative` / `run_normalize` /
   `run_pipeline`，需先有该机构版式模板；没有模板时 `draft_template.py` 起草 +
   人工确认）；纯文本来源 → 仿 `loaders.load_synth()` 写一个载入函数
2. `python3 gen_artifacts.py --engine-out <产物目录> --case-name <名>`（见"命令 A"）
3. 用 `reconcile.py --artifacts <底稿目录>` 检查新报告；`checks` 是产物驱动的，
   **换案例不用改检查代码**
